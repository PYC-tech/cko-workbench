# cKO 工作台

> 条件性敲除（conditional knockout, cKO）小鼠 / 大鼠的**本地桌面管理程序**。
> 鼠只档案、基因分型、谱系溯源、笼位、胶图与工作日志，全部保存在你自己指定的文件夹里——数据完全本地，不上传任何服务器。

一个为「一个人 / 一个课题组自己养一群敲除鼠」这个场景做的轻量工具：不依赖数据库服务、不需要联网、双击就能用，放进 U 盘也能带走。

## 为什么做这个

养敲除鼠的日常，绕不开三件事：**谁是谁的孩子**、**这一批鉴定谁中了**、**上次是谁在哪个笼子里测的**。

用 Excel 管，最容易出两个问题：一是**父母关系**记着记着就断了；二是**「没测」和「测了是阴性」被混成一谈**——后者会直接把选鼠选错。

cKO 工作台针对这两点做了硬约束：

- 谱系以「父 / 母」真实引用保存，可交互画出**家族树**；
- 明确定义 **「未提及 ≠ 阴性」**：口述里没说到某个指标，就记为「未提及」，绝不擅自当成阴性或默认值。

## 主要功能

| 模块 | 说明 |
|---|---|
| **总览** | 项目统计（鼠只 / 存活 / 目标鼠 / 位点 / 批次）、目标鼠清单、近期批次 |
| **鼠只档案** | 表格含耳号、性别、周龄、状态、笼位（彩色标记）、来源批次、各指标基因型、目标、父本、母本；可按列排序，目标鼠整行高亮 |
| **谱系** | 交互式家族树：分层布局 + 亲子连线 + 配偶虚线 + 笼位分组框 + 世代标注（F0/F1…）；点任意节点即以它为中心重新展开，可「只溯源」或「上下都看」 |
| **笼位** | 按笼分组，自动区分繁殖笼 / 饲养笼，列出成员 |
| **鉴定批次** | 一次鉴定一批；记录每只鼠的判读结果；**一个批次可挂多张胶图**（上传多选 / 删除 / 点开放大） |
| **口述录入** | 语音转文字 → 交给任意大模型按提示词卡片整理 → 粘贴回来 → 本地解析 → 确认表 → dry-run → 落盘 |
| **工作台日志** | 独立于鼠只的自由记录，可按月归档，可挂照片 |
| **全局位点档案** | 指标（位点）**可自定义**：名称、简称、取值、默认值都能改；换一个基因敲除，只需改名字 |
| **备份与恢复** | 每次写入前自动快照，保留最近 N 份，可预览并恢复 |

## 快速开始

### 方式一：直接下载安装包（推荐给使用者）

> 本仓库**只放源码**。Windows 安装包请到本仓库的 **[Releases](../../releases)** 页面下载。

1. 打开本仓库的 **Releases** 页面（GitHub 仓库右侧栏，或地址栏后加 `/releases`）；
2. 下载最新版的 `cKO工作台-安装程序-x.y.z.exe`（Windows 64 位）；
3. 双击安装（可自选安装目录，会自动创建桌面与开始菜单快捷方式）；
4. 打开即用——首次启动会自动在安装目录同级创建一个数据文件夹，并载入一份**内置示例数据**（虚构），无需任何选择或确认。

> 示例数据长什么样：30 只鼠、10 个笼位、4 个鉴定批次、F0→F1→F2 三代家系（含一例耳标脱落改号与一例复检改判），用来直接体验「谱系」与「笼位」两个视图。全部虚构，随时可删。
>
> 数据目录里已有项目时不会重复载入；想手动再载一份，去「设置 → 内置示例数据 → 载入示例项目」。
>
> 自己写示例数据：改 `build/make-demo-seed.js` 里的家系表，跑 `node build/make-demo-seed.js` 重新生成 `src/renderer/seed/demo.js`（生成前会跑家系断言，父母悬空或耳号重号会直接报错）。

> 想换数据位置：进「设置 → 更改数据目录」。
>
> 安装包未做代码签名，Windows 首次运行可能提示「已保护你的电脑」——点「更多信息 → 仍要运行」即可。

### 方式二：从源码构建（推荐给开发者）

```bash
git clone <your-repo-url>
cd cko-workbench
npm install
npm run dist        # 生成安装包 → dist/cKO工作台-安装程序-*.exe
npm start           # 或直接以开发模式运行
```

> 首次 `npm install` 会下载 Electron 运行时（约 100 MB+），请保持网络畅通。
>
> 不想本地构建？打一个 tag（如 `git tag v1.0.0 && git push --tags`），仓库内置的 GitHub Actions 会自动构建并把安装包挂到 Release 上（见 `.github/workflows/build.yml`）。

## 使用指南

### 1. 数据存在哪

程序的数据（鼠只、批次、胶图）统一放在一个「**数据目录**」里，默认在安装目录同级；你也可以在「设置」里换成任意文件夹（比如移动硬盘）。**整个文件夹可以整体拷贝、备份、换机**。

### 2. 建项目与自定义指标

点项目切换器旁的「**+ 新项目**」，在对话框里可以**直接编辑指标（位点）的名字**：

- 默认带三个通用指标：`目标基因-Flox` / `目标基因-KO` / `Cre 驱动系`；
- 做别的基因敲除时，把名字改成你的基因名即可；也可以「+ 加一个指标」或删除不需要的。

指标的三种模型：

- **biallelic**：二倍体等位，按凝胶条带数判定（无带 / 1 条带 / 2 条带）；
- **binary**：二分判定（有带 / 无带）；
- **transgenic**：转基因品系。**Cre 之类必须选它**——否则「双带 × 双带」的纯合携带者会被漏判，配种概率也就错了。

### 3. 录一次鉴定

两条路：

- **手写批次**：在文本框里按 `耳号 | 性别 | 指标=取值` 每行一只，点「解析并预览」；
- **口述录入**：点「复制提示词卡片」→ 把卡片内容和你语音转出的文字一起发给大模型 → 把模型返回的规范文本粘回程序 → 解析。

解析后会出现一张**确认表**，明确区分每一格的来源：

| 来源 | 含义 |
|---|---|
| 明确（stated） | 你在这一只鼠上直接说了取值 |
| 批次推得（batch-stated） | 来自 `@本批默认` 这种整批统一陈述 |
| 默认（default） | 你没提，但该指标设了项目默认值 |
| **未提及（omitted）** | 你没提，也没有默认值 —— **灰虚线框，绝不等于阴性** |

确认无误后点「生成变更预览」→「确认写入」，才会真正落盘。

### 4. 挂胶图

「鉴定批次」→ 点某个批次 → 「**+ 添加胶图（可多选）**」→ 可一次选多张。图片真实保存到数据目录，可删除、可点开放大。

### 5. 看谱系与笼位

- 「谱系」页：选一只鼠作为中心，自动展开它的祖先（可选后代），并标出世代与同笼分组；
- 「笼位」页：按笼查看全部成员。

### 6. 结果会变：改判与鼠只修改

鉴定是个长期、动态的过程——第一次跑不准、耳标掉了换了号、原来判为目标鼠后来又不像了，**这些都要能改，而且改得留痕**。

- **基因型改判**：再录一次鉴定即可。解析后会进「变更预览」，明确列出「将覆盖旧值：001 · 目标基因-KO：pos → neg」；写入时把旧值存进 `prev`，**不是静默覆盖**。
- **鼠只本体修改**：鼠只详情 →「**编辑鼠只资料**」，可改耳号、性别、出生日期、状态、笼位、备注。改动会**自动记一条事件**（如「资料修改：耳号 091 → 105」），进事件时间线可追溯。耳号改动会做**重号检查**。

### 7. 智能体收件箱（Agent 入口）

给自动化/智能体留的数据入口：**数据目录下的 `_inbox/` 文件夹**。

1. 让智能体把整理好的规范文本写成 `.txt` / `.md`（或含 `text` 字段的 `.json`），丢进 `_inbox/`；
2. 程序里打开「**口述录入 → 收件箱**」，点「检查收件箱」（启动时也会自动提示）；
3. 点「载入并解析」→ 出现在下面 → 核对**确认表** → 确认写入；
4. 处理完的文件自动归档到 `_inbox/_done/`。

> 设计上**刻意保留人工确认环节**：智能体只能"投递"，不能直接改库，避免它背着你动数据。

### 8. 导出

「鼠只档案」页 →「**导出 CSV**」，把当前项目的鼠只表（含各指标判读、目标、父本母本、周龄、笼位）导出为 CSV，带 BOM，**Excel 双击不乱码**。

### 9. 备份

「设置 → 立即备份」可手动快照；程序在**每次写入前也会自动快照**，可在设置页预览并恢复。

## 技术架构（Pipeline）

程序是标准的 **Electron 三层结构**，主进程负责所有磁盘 IO，渲染层不碰文件系统，中间由一层白名单桥接。

```
┌──────────────────────────────────────────────────────────────┐
│  渲染层 (Renderer)  src/renderer/                             │
│  原生 JS（无框架），按 index.html 顺序加载：                    │
│  genetics → model → store → templates → migrate → parse        │
│           → app → ui → views → main                            │
│  · store.js 是唯一数据出入口（有磁盘就写盘，无则降级调试）      │
│  · 所有用户输入走 textContent / escapeHtml（防 XSS）           │
└───────────────▲──────────────────────────────────────────────┘
                │  window.__CKO_BRIDGE__.*（只暴露白名单方法）
┌───────────────┴──────────────────────────────────────────────┐
│  Preload 桥  src/preload/index.js                             │
│  contextBridge + 显式别名表（消除频道名冲突）                   │
│  contextIsolation: true, nodeIntegration: false               │
└───────────────▲──────────────────────────────────────────────┘
                │  ipcRenderer.invoke → ipcMain.handle
┌───────────────┴──────────────────────────────────────────────┐
│  主进程 (Main)  src/main/                                     │
│  index.js  窗口与生命周期、cko://media 协议、单实例锁           │
│  ipc.js    全部 IPC handler（统一 {ok,data} / {ok:false,...}） │
│  vault.js  磁盘后端：路径白名单、原子写、快照、图片落盘         │
└──────────────────────────────────────────────────────────────┘
```

### 关键设计

- **数据流**：`视图 → app.js（状态与业务） → store.js → bridge → ipc.js → vault.js → 磁盘`。视图层不直接读写文件。
- **原子写**：写 `.tmp` → `fsync` → `rename` 覆盖（Windows 上对 `EPERM/EBUSY` 退避重试），避免写一半损坏。
- **写前快照**：覆盖文件前先复制进 `backups/<时间戳>/`，超量自动轮转。
- **路径白名单**：`vault.resolve()` 拒绝绝对路径、`..`、盘符，渲染层拿不到任意文件系统权限。
- **慢介质保护**：目录校验用**异步** IO 并加超时，网络盘 / 移动盘卡顿不会冻结主进程。
- **遗传学引擎**（`genetics.js`）：`genotypeToCall` / `crossLocus` / `crossAll` / `targetProbability` / `chi2sf`（Lanczos 近似），纯函数，位点定义由参数传入。
- **口述 DSL**（`parse.js`）：`@日期` / `@泳道顺序` / `@本批默认` + 数据行 `耳号 | 性别 | 指标=取值`；`?` 表示未提及。指标与取值靠 `locus.aliases` 派生匹配，代码里不写死。
- **旧版迁移**（`migrate.js`）：可从早期「单文件 HTML 台账」导入；位点与目标定义从 HTML 内联的 `LOCI` / `TARGETS` 中原样读取，无需内置模板。解析器自己实现（**不依赖 `eval`**，兼容渲染层 CSP）。

## 数据格式

数据目录（vault）布局：

```
<数据目录>/
├─ 工作台.json                    # 项目索引 / 当前项目 / 设置
├─ archive/loci-archive.json      # 全局位点档案（带版本）
├─ projects/<项目id>/
│  ├─ project.json                # 指标 / 目标 / 元信息
│  ├─ rats.json                   # 全部鼠只（含事件时间线）
│  ├─ sessions/<序号>-<日期>.json # 一批次一文件
│  ├─ logs/<年-月>.json           # 工作日志按月分片
│  └─ photos/{gels,rats,logs}/    # 胶图与照片
├─ backups/<时间戳>/              # 写入前自动快照
└─ .cko/                          # 锁与写入日志
```

全部是**纯文本 JSON + 图片文件**，透明可读，也方便用脚本处理。

## 开发与打包

```bash
npm start          # 开发模式运行
npm run dist:dir   # 生成免安装目录 dist/win-unpacked
```
